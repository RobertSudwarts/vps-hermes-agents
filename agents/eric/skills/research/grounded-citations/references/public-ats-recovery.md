# Selective public vacancy recovery

Use only the applicable source section. These are observed retrieval patterns,
not promises that an endpoint still works or permission to change a collection
adapter. `job-discovery` owns watchlist/adapter validation and full-board coverage.

## Retrieval and failure rules

Save original bytes, request URL, HTTP status, retrieval time and extracted text
with source-to-file mapping. Inspect substantive content before registering support.
Do not repeat a search-only extraction backend or alter agent configuration; use
available public HTTP/HTML/PDF tools. Never install dependencies for a recovery.

For a default-client 403, at most one normal browser User-Agent/Accept retry is
reasonable if no access instruction or Retry-After forbids it. Honour rate limits;
record both outcomes and validate the body. No proxy/account/configuration bypass.
Check HTTP/document encoding before parsing; correct proven decoding from bytes,
record it, and never hand-edit mojibake into guessed names. Keep tokens redacted.
Ignore unrelated appended articles, related-job cards and corporate boilerplate.

Follow observed print/download/accessible links from the actual page (including
Onlyfy print links), never guessed job handles. Inspect Content-Type and `%PDF`
before decoding. Save PDFs and use the generic `pdf` skill’s extraction reference/helpers with an already available parser; load its OCR reference only for scanned or incompletely extracted pages. Preserve URL, retrieval time and page-to-evidence mapping here. Extraction does not trigger career production. Extract all relevant specification pages and
confirm employer, title, responsibilities and requirements. Register the print
URL separately and still inspect the normal live route for status. An imprint
proves an office address, not vacancy location/attendance. If extraction remains
blocked, label the gap or search-only evidence without inventing facts.

## Structured HTML and ATS variants

- **JSON-LD:** parse the actual `JobPosting` from an object, array or `@graph`.
  Retain canonical URL ID separately from `identifier.value`; inspect description,
  `jobLocation` and body/attendance terms, not adjacent role cards.
- **Attrax:** discover `data-option-id`/`aria-label` filters from this board or its
  observed published controller, never another employer's IDs. Use offered page
  sizes and observed options/page parameters. Reconcile each filtered pool to its
  displayed count, then deduplicate their union. Remote filters and city variants
  establish neither Austria eligibility nor independent headcount.
- **Ashby:** derive the board name from observed material; use the public posting
  feed and match exact UUID. Preserve `descriptionPlain`, `employmentType`,
  `workplaceType`, `isListed`, `jobUrl`, `applyUrl`. Resolve country-board `locationId`
  against embedded location names and reconcile with primary/secondary feed
  locations. Save full feed and subset before counts. For embedded
  `window.__appData`, use `JSONDecoder.raw_decode` after the observed assignment,
  retaining HTML/extracted posting and matching UUID/title/location/listed state.
  This proves role-linked data, not a rendered/tested interactive form.
- **Greenhouse:** retain original `content`; decode escaped HTML before parsing
  tags, then decode text entities. Save readable full requirements separately from
  feed evidence. A source lacking descriptions is not complete role evidence.
- **Workday:** derive host, tenant/site and full `job/...` slug from the observed
  canonical URL/configuration. Public CXS detail may be available at
  `https://<host>/wday/cxs/<tenant>/<site>/<job-path>`. Never invent a tenant/slug.
  Use appropriate browser User-Agent/JSON Accept and the bounded retry above.
  Validate `jobPostingInfo.title`, `jobReqId`, `externalUrl`, `jobDescription`,
  `location` and `additionalLocations`; URL suffix and requisition may differ.
  Refused API access is not closure. For token-based board collection and pagination,
  load `job-discovery` source onboarding; no credentials/tokens in saved evidence.
- **SmartRecruiters:** reconcile `limit`/`offset` pages to `totalFound`, deduplicate
  IDs and inspect exact returned detail references and `postingUrl`/`applyUrl`.
  Shared `refNumber` may link several location IDs to one vacancy. Compare posting
  location/street, HTML microdata and custom country fields; copied German
  benefits/Munich metadata on an Austrian variant is a conflict to flag, not proof
  either that all offices are eligible or that the local posting is invalid.
- **Recruitee/SuccessFactors/Personio:** the existing discovery helper owns validated
  collection contracts; consult its contract/onboarding reference when operating
  those feeds rather than inventing a second parser.

## Before claiming verification

Check final URLs and bodies of observed application links without submitting or
authenticating. A generic redirect or error page with HTTP 200 is not the exact
vacancy. If the specification is substantive but Apply is refused, record the
route limitation separately; never call the interactive form tested. Keep the
lead provisional where material requirements/status cannot be verified.

The citation parser can truncate literal parentheses in URLs. Prefer an actually
observed percent-encoded canonical URL when available; register it and regenerate
Sources rather than hand-editing mappings or fabricating a canonical URL. If no
working representation is available, report the checker limitation.

Unused/blocked discovery leads stay in retrieval metadata, not as support for
substantive claims. Normal verifier warnings can document unused sources; never
pad prose with irrelevant citations to satisfy strict mode. Check actual entailment
and currency independently of ledger integrity.
